# 滚动驱动动画 (Scroll-Driven Animation) 概念指北

## 背景与需求
当前的交互模式为：“滚动到某个特定组/图片可见时，**触发一次性的过渡动画**（如从边界外固定飞入，采用 CSS `transition` 完成）”。  
新版需求变更为：**真正的跟随滚动而动的滚动驱动动画 (Scroll-Driven Animation)**，不依赖单纯的进入视口即触发，而是与用户的滑动条 (Scroll Progress) **1:1 绑定映射**。

> **核心原则**：不滑动就不动，滑动多少就对应渲染出多少动画进度，任意时刻停下（甚至反向滑动），动画也会定格或回退到相应的精确中间态。可参考 [ScrollMagic](https://scrollmagic.io/examples/basic/simple_tweening.html) 的执行方式。

## 数据结构设计理念 (示例)

未来的 `productConfig` (或扩展配置) 应当在原来的浮层 `anim` 配置基础上，支持插值区间映射方案，例如：

```json
{
  "overlays": [
    {
      "id": "ov_01",
      "type": "card",
      "pos": { "x": 50, "y": 50 },
      "scrollAnim": {
        "triggerStart": 50,   // 定义这个容器或者页面的滚动进度起点 (例如 0~100 进度系统下的 50)
        "triggerEnd": 80,     // 滚动进度的终点
        "mapping": {
          // 意图：当主滚动条在 [50, 80] 区间运动时，将该区间映射到 scale [0.5, 1.0] 的缩放比例
          "scale": [0.5, 1.0],
          // 同时透明度在此区间从 0 到 1 线性变化
          "opacity": [0, 1]
        }
      }
    }
  ]
}
```

## 执行逻辑推演

1. **区间数学映射 (Interpolation)**：  
   用户滑动详情页到底部，监听器 (`onScroll` 或 wx.createIntersectionObserver / ScrollTimeline)。  
   假设总体可滚动范围被标准化为 `0 ~ 100`，当前滚动进度为 `P` (例如 `P = 65`)。
   
   执行判断：
   - 当 `P < 50` 时，渲染最初始状态 (scale=0.5, opacity=0)。
   - 当 `P` 在 `50 ~ 80` 之间时，进行线性插值计算。
     例如 `P = 65` 正好处于 50 和 80 的绝对中点 (50%)：
     `scale` = `0.5 + (1.0 - 0.5) * 50%` = **0.75**  
     `opacity` = `0 + (1 - 0) * 50%` = **0.5**
   - 当 `P > 80` 时，渲染最末端状态 (scale=1.0, opacity=1)。

2. **渲染层实现**：
   - 小程序端不再使用 `transition: transform 650ms`，因为我们不想要时间上的补间，而想要基于滚动位置的补间。
   - 小程序可以通过 `scroll-view` 的 `bindscroll` 获取 `scrollTop` 实时计算。或者更先进的做法：利用小程序的类似于 WXS 响应极速滑动的能力，将插值计算过程放在 WXS 中。
   - 对 DOM 进行动态的 inline `transform: scale(0.75)` 切片级重绘，或者直接修改 CSS 变量。

## 对 Admin Editor 的改造要求
为了实现这种所见即所得的可视化配置，Admin Editor 必须具备：
1. **统一的时间轴/滚动轴面板**：不再是单独配置一个 `duration: 650ms`。必须有一个模拟详情页的纵向轨道，以及明确标出 `Start (50)` 和 `End (80)` 相对于视口发生点的滑块。
2. **多状态抓拍/打点能力 (Keyframe-based)**：允许用户选择在起始状态该元件的样子（放到多大、透明度多少、平移到哪里），再选择在终止状态的样子，编辑器内部通过插值映射把这两条“关键帧”计算为如上所示的 JSON 并导出。

## 架构细化：双层滚动坐标系 (Two-Tier Scroll System)

在实际的落地场景（尤其是类似 Apple 官网的高级展示或我们目前的小程序架构中），页面的滚动不仅仅是单一维度的一缕到底，而是“组与组滑动”与“组内图像滑动”的结合。

为了实现最顶级且不突兀的体验要求，**只有在跨越组边界切换时，才需要引入带物理引擎的弹簧和阻尼感；而在组内浏览内部长图时，只需要单纯的自由滚动以及无摩擦感地映射 Scroll-Driven 动画**。

### 交互模型范例

假设有两个组：**Group A (含图片 1, 2, 3)**、**Group B (含图片 4, 5)**。依次纵向阵列。

1. **内层 - 组内自由平滑滚动 (Inner Track)**
   - 当用户在 Group A 内滑动时（即横跨在图片 1, 2, 3 之间上下滑动）：
     - 此时不触发任何特殊的吸附、阻尼或弹簧效果。这应该是一次单纯且纯净的手滑跟随体验。
     - **Scroll-Driven 动画的附着**：此时基于内部实际划过的位移（例如 `groupY`），对应各图片配置下的 `triggerStart/End`，实时线性插值计算透明度或位移（如文字从边界飞入）。这就要求引擎是绝对跟手的 1:1 数值输出，没有任何弹性补偿（防止动画错位或抖搐）。

2. **外层 - 组间弹性边界 (Outer Track)**
   - 当用户划到了 Group A 的最底端（图片3 的尽头），此时试图继续向滑去触碰 Group B（图片4）时：
     - 引擎判定到达了**组级刚性边界 (Group Boundary, 处于 3 和 4 交界)。
     - 此时继续尝试“硬滑”会感受到阻尼（越拉越紧），一旦越过换组阈值并松开手指：
     - **触发外层轨道弹簧引擎**：带有阻尼地弹至下一组开头，造成一次明显的“翻阅/入场段落感”。
   - 这种边界弹性只发生在切换大 Section 时介入。

**总结备忘**：
- **"组边界跨越"** = 断层的翻页行为，强调物理弹簧、滞后阻尼、吸附 (Snap)。
- **"组内连贯浏览"** = 连续的阅读行为，强调零阻力滑动，且在滚动轨迹上百分百跟手渲染组件各节点的 Scroll-Driven 进出场动效。

### Element Context 标尺补充说明

虽然采用全局绝对进度 (0~100) 最容易在底层概念上理解（并在 Editor 中画出一条绝对的“纵向坐标轴”供滑块拖拽），但这种模式有一个致命的维护弱点：**如果在顶部插入或删除了一张商品图，整个组（或层级）的总高度发生变化，那么所有下方组件原本设置的绝对进度 `triggerStart: 60` 会因为总比例的分母改变而全部错位，造成大面积灾难。**

**核心解决策略：**
未来在编辑器标尺或引擎计算层面，必须将标尺改为 **"Element Context" (元素相对进度)** 模式。
彻底摒弃依赖 0~100 的全局滑动条，而是基于**目标元素自身何时进入/离开视口 (Viewport)** 进行相对打点，比如约定：
- `triggerStart: "top enter"` (当前图组顶部刚开始露出视口时，进场动画开始)
- `triggerEnd: "center center"` (当前图组到达屏幕中央时，进场动画结束)

这也是知名滚动驱动库（如 GSAP ScrollTrigger 或 CSS Scroll Timeline）的行业标准实现方案。一旦采用，不论运营在后台怎么拖拽调换图片和组的排序，每个 Overlay 动画都是绝对独立的。

## 总结
将“时间”维度的过渡（Time-based transition），全面转向“空间/进度”维度的过渡（Scroll-driven interpolation）。这是对高级数字展厅或 Apple 官网风格落地页的常见实现技巧。

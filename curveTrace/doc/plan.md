# WebAR 弧面追踪与校准项目实施记录及优化规划 (Curved Label Tracking Plan & Record)

本项目致力于解决 WebAR 中，将平面视频/图片贴合在真实物理圆柱弧面（如饮料瓶、酒瓶）上时所面临的**追踪延迟（抖动漂移）**、**视差滑动（贴合度低）**以及**对齐偏差**等行业痛点。通过自研的 OpenCV.js 弧面追踪引擎，彻底抛弃了原先只能用于纯平海报的 MindAR，实现了低延迟、高贴合度的 AR 沉浸式效果。

---

## 1. 已完成的工作 (Completed Work)

我们对 [impl.html](file:///d:/workspace/tools/curveTrace/impl.html) 进行了全方位的重构与优化，具体工作如下：

### A. 弃用 MindAR，自研 OpenCV.js 追踪引擎
* **ORB 特征匹配**：引入 OpenCV.js，当前在后台以 $640 \times 480$ 分辨率的跟踪画布实时捕获相机帧，利用 ORB（Oriented FAST and Rotated BRIEF）算法提取特征点并进行 Hamming 汉明距离匹配。早期版本曾使用 $320 \times 240$，现已升级。
* **PnP 位姿解算**：基于 2D 特征点与 3D 圆柱投影点云的映射关系，优先使用 `cv.solvePnPRansac`（及 `cv.solvePnP` 容错备用）在每一帧求解相机的三维位姿（`rvec` 旋转向量与 `tvec` 平移向量）。
* **相机位姿映射**：使用 Rodrigues 变换将 OpenCV 相机坐标系（$Y$-down, $+Z$-forward）完美映射至 Three.js 坐标系（$Y$-up, $-Z$-forward），直接通过 inverse modelView 矩阵反向驱动虚拟相机的平移与旋转。

### B. 弧面几何重建与纹理映射 (Cylindrical Mapping & UV Setup)
* **圆柱点云投影**：实现了根据瓶身尺寸（上下半径 $R_{top}/R_{bottom}$、高度 $H$、弧度张角 $\theta$）动态将 2D 像素坐标映射为 3D 圆柱曲面坐标的算法：
  $$X_i = R_y \cdot \sin(\theta_i)$$
  $$Y_i = (H/2 - v_i) \cdot scale$$
  $$Z_i = R_y \cdot \cos(\theta_i)$$
* **自适应截台 (Frustum) 支持**：支持上下半径不一致的瓶身（渐变斜度瓶身），在计算点云高度 $Y$ 时，线性插值计算当前高度下的圆柱半径，保证完美贴合。
* **正对视角（+Z轴对齐）与防镜像**：将虚拟圆柱网格的起始张角 `thetaStartVal` 修改为以 $90^\circ$（即 $+Z$ 正前方）为中心对称展开。配合 Three.js 纹理的水平镜像翻转（`repeat.x = -1`, `offset.x = 1`），消除了 $90^\circ$ 画面旋转偏差及镜像反转问题，使视频画面在默认参数下即刻完美对齐酒标。

### C. 内存泄露消除与性能调优
* **WASM 内存回收**：消除了在 `processFrame` 运行循环中频繁分配 `cv.Mat` 造成的 WebAssembly 堆内存泄露。实现了全局预分配 `maskMat` 并复用。
* **3D 坐标预计算缓存 (Coordinate Caching)**：实现了 `ref3DPoints` 坐标缓存机制。点云坐标仅在加载图样或拖动标定滑块时重新计算，避免了高频每帧三角函数计算。
* **多尺度目标金字塔**：当前已对 `assets/mark.jpg` 建立多尺度 ORB 特征层（如 `1.0 / 0.75 / 0.5 / 0.35`），用于缓解远近距离下的尺度不匹配问题。

### D. 双模调试与实时标定
* **Live AR 模式与 3D Preview 模式**：支持一键切换。在 3D 预览模式下，利用 OrbitControls 可自由旋转观测虚拟圆柱瓶身，以及底层的半透明 `mark.jpg` 酒标贴图材质指引，便于脱机微调参数。
* **实时 matches 数量反馈**：在状态徽章实时显示当前帧匹配成功的特征点数量（如 `DETECTED (35 matches)`），便于用户研判跟踪质量。

### E. 异常值过滤与几何校验 (Outlier Rejection & Pose Validation) [NEW]
* **单应性 RANSAC 预过滤**：在 PnP 解算前，利用 `cv.findHomography` 对特征点执行 RANSAC 过滤（重投影阈值 8.0 像素），筛除不符合平面刚性几何规律的背景噪声（键盘、桌面、屏幕杂斑），提取最纯净的 inlier 特征子集。
* **内含比率校验 (Inlier Ratio Check)**：引入 `InlierRatio >= 20%` 校验条件，有效防止背景杂乱产生的误触发。
* **几何位姿双重校验**：对 PnP 输出的平移向量执行有限数值判定及 $Z$-depth 判定（`tD[2] > 0.1` 必须在相机前方）。通过分解反向相机世界矩阵，计算相机离瓶身坐标中心的实际距离，滤除超出 $[0.5, 25.0]$ 范围的异常跳变，彻底消除视频贴图“满天飞”或提前错误触发的现象。

### F. 相机内参与调试能力补强 [NEW]
* **FOV / 焦距系数调节**：已新增 `fovScale` 配置与 UI 滑块，用于实时修正 `initCameraMatrix()` 中的经验焦距，降低贴片随视角移动时的视差滑动。
* **调试统计扩展**：调试面板已增加 `Best Scale`、`Dynamic Min`、`Inlier Ratio` 等指标，用于判断当前是匹配不足、尺度选择错误还是 PnP 质量不足。

### G. 混合跟踪实验（ORB + LK 光流）[NEW]
* **光流快路径**：已接入 OpenCV.js 的金字塔 Lucas-Kanade 光流（`cv.calcOpticalFlowPyrLK`），在识别成功后优先使用上一帧稳定点做高频跟踪，降低“每帧全量 ORB 重定位”带来的感知延迟。
* **跟踪状态机**：当前已引入 `SCANNING / RELOCALIZING / TRACKING_FLOW` 状态，用于在全局识别、局部快跟踪和重新锁定之间切换。
* **当前实验结论**：响应速度相比纯 ORB + PnP 逐帧重定位已有改善，但稳定性仍弱于理想目标，特别是在快速转动、遮挡和曲面透视变化时，光流点集容易污染，导致后续位姿不稳。

### F. 目标图特征可视化 (Target Keypoints Visualizer) [NEW]
* **关键点渲染**：在标定面板底部增加了“目标特征点可视化”调试 Canvas，直接绘制出 `assets/mark.jpg` 提取的所有 ORB 特征点及其尺度范围，帮助开发者判断样本图像纹理质量。
* **溢出滚动布局**：针对大尺寸样本图像，设置了滚动容器（`overflow: auto; max-height: 200px`），防止图像溢出标定面板。

## 2. 核心算法思想 (Core Algorithmic Principles)

### A. 相机内参及投影自适应裁剪补偿 (Aspect Ratio & Fit Cover Compensation)
为了防止相机流被 CSS `object-fit: cover` 裁剪拉伸后与 Three.js 三维物体产生视差偏差，我们通过计算屏幕分辨率与相机原生分辨率的缩放比，重构了 Three.js 摄像机的投影矩阵：
$$Scale = \max(W_{screen}/W_{video}, H_{screen}/H_{video})$$
$$f'_{x} = f_x \cdot Scale_{nativeX} \cdot Scale$$
通过这种方式，将当前 $640 \times 480$ 追踪画布下的内参投影无缝缩放到全屏视口，保证了虚拟模型在屏幕上的成像位置与真实瓶子完全重合。早期版本使用过 $320 \times 240$，现已升级。

### B. 响应度控制与平滑插值
引入用户可调参数 `lerpFactor`。当前在 Fast 模式下，`lerpFactor` 已被降级为“微平滑强度”，默认值约为 `0.04`，主要用于抑制轻微抖动而不是显著延迟地追随目标；若接近 `0`，则更偏向零时延直接跟随；若增大，则会换取更平滑但更慢的响应。

## 3. 后续需要改进的地方与优化方向 (Future Improvements & Issues)

### 1) 实际测试痛点分析 (Current Testing Issues)

> [!WARNING]
> **痛点一：识别距离过短（必须贴近摄像头约 5cm 才能触发识别）**
> * **根本原因**：
>   1. **早期画布分辨率过低是首要原因之一**：早期实时跟踪帧 canvas 设为 $320 \times 240$。当物理瓶身距离镜头超过 5cm 时，酒标图像在画面中占比变小（例如缩小为 $60 \times 120$ 像素），降采样导致细节严重丢失，ORB 特征匹配点数量直接跌破阈值，致使 RANSAC/PnP 校验无法通过。当前已升级至 $640 \times 480$，该问题已部分缓解，但不再是唯一主因。
>   2. **早期存在尺度特征空间不匹配，当前已部分缓解但未根治**：目标酒标分辨率高（$304 \times 666$），早期相机流在降采样后清晰度无法对应，导致两端特征空间不匹配。当前虽已通过 $640 \times 480$ 跟踪分辨率与多尺度金字塔建图缓解该问题，但在曲面标签、快速运动和大视角变化下，仍会因为非平面形变与局部错配造成不稳定。
> * **解决方案**：
>   1. **已完成：升级跟踪分辨率**：已将 `trackW` / `trackH` 提升至 $640 \times 480$，保留更多远距离细节。
>   2. **已完成：目标图像金字塔下采样建图**：当前在提取 `assets/mark.jpg` 特征时，已同时建立多尺度金字塔，以改善远距离匹配能力。
>   3. **已完成：自适应匹配截断**：已根据当前命中的尺度层动态调整 `minMatches`，降低小尺度层的误判风险。
>   4. **剩余问题**：即使完成以上优化，快速运动与大视角变化下仍会掉点，说明当前问题已经不只是分辨率或阈值问题，而是曲面视觉变化与纯视觉 Web 跟踪架构边界共同造成的。

> [!WARNING]
> **痛点二：贴合度不够（存在视差抖动或贴合不紧密）**
> * **根本原因**：
>   1. **虚拟焦距/内参不准确**：当前 `initCameraMatrix()` 中的焦距采用经验估算值（$fx = fy = trackW \cdot 1.05$）。如果手机摄像头的真实视场角（FOV）与此经验估算值偏差较大，PnP 求解出的深度（$Z$ 轴距离）和俯仰角就会有系统性误差，导致视频贴片随视角移动而产生偏移（Parallax Sliding）。
>   2. **畸变系数设为零**：没有对手机镜头普遍存在的径向畸变（Lens Distortion）进行纠正。
>   3. **缺少视觉-惯性预测与曲面专用约束**：当前实现仍主要依赖相机帧本身做视觉跟踪，尚未引入 IMU / VIO 式姿态预测，也没有建立专门针对圆柱曲面标签的强几何约束，因此“响应速度”和“稳定性”会互相牵制。
> * **解决方案**：
>   1. **已完成：新增“焦距系数 / Camera FOV”调节滑块**：当前已支持使用 `fovScale` 在 Live AR 或 3D Preview 下手动调校焦距估算。
>   2. **已完成：PnP RANSAC 与轻量跳变拒绝**：当前已优先使用 `solvePnPRansac`，并加入大位移 / 大角度跳变门控，防止贴片“飞走”。
>   3. **已实验：基于光流的帧间快路径**：当前已加入 `calcOpticalFlowPyrLK` 快速跟踪，响应速度有所改善，但稳定性仍不足。
>   4. **待验证方向**：后续更值得优先验证的是“低频重定位 + 高频跟踪 + IMU 预测 + 圆柱约束”的混合架构，而不是继续单纯加大平滑或阈值调整。

### 2) 基于光流法 (Optical Flow) 的帧间运动估计
* **当前状态**：已在 OpenCV.js 中接入金字塔 Lucas-Kanade 光流（`cv.calcOpticalFlowPyrLK`）作为高频跟踪快路径，并引入 `SCANNING / RELOCALIZING / TRACKING_FLOW` 状态机。
* **当前收益**：相较纯 ORB + PnP 逐帧重定位，响应速度已有所改善，快速运动时的感知延迟下降。
* **当前问题**：稳定性仍不足，尤其在圆柱曲面标签的透视变化、局部高光、遮挡与快速转动下，光流点集容易污染，进而影响后续 PnP 位姿。
* **结论**：光流适合作为低时延跟踪层，但不能单独承担完整追踪任务；后续仍需要配合低频重定位、IMU 预测和圆柱约束联合使用。

### 3) 当前路线判断：是否需要 C++ / 更换技术方案
* **当前主要瓶颈并不只是 JavaScript 执行效率**：更核心的问题是纯视觉 Web 跟踪架构本身缺少视觉-惯性预测与曲面专用约束，因此“响应速度提升后稳定性下降”的矛盾不会因单纯换语言而自然消失。
* **C++ / WASM 是二阶段性能优化选项，而不是当前第一优先级**：将热点模块迁移到 C++/WASM 可能带来部分性能收益，但不会自动解决快/稳冲突。
* **纯 Web 路线的下一步应优先验证混合架构**：即“低频重定位 + 高频光流跟踪 + IMU 预测 + 圆柱先验”。
* **如果纯 Web 仍无法满足体验目标**：再评估原生 ARKit / ARCore / Unity AR Foundation 等更成熟的移动 AR runtime。

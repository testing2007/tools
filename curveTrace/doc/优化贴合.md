确实，**无缝贴合不是延迟问题，而是几何问题**。你现在已经能“跟上”，但贴不上，说明下一步不要再主要优化性能，而要做 **标定 + 曲面真实建模 + 局部配准**。

一句话判断：

> 你现在是用“理想圆柱/锥台模型”去贴真实瓶身，但真实酒瓶、真实酒标、摄像头画面、视频纹理之间没有完成同一套几何标定，所以一定会有边缘偏移、上下错位、角度变化后漂移。

## 1. 先接受一个现实：单圆柱模型很难做到商业级无缝

你现在的核心模型是：

```js
X = r_at_y * Math.sin(theta)
Y = ...
Z = r_at_y * Math.cos(theta)
```

这适合“规则圆柱”。但真实瓶身通常不是：

```text
完美圆柱
标签完全平整
标签宽高比例准确
瓶子上下半径线性变化
摄像头无畸变
视频内容和酒标图完全同比例
```

8th Wall 的曲面目标支持 cylinder / cone 类型，不只是把视频贴到 Three.js Cylinder 上，而是在创建目标时让用户指定曲面类型和曲率，用目标训练包去约束运行时识别。公开资料里也提到它面向圆柱/圆锥物体，比如瓶、罐、杯，而不是简单平面 target。([arXiv][1])

另外，PnP 本身要求准确的 3D 点和 2D 投影点，并且通常假设相机内参已知；如果相机内参、曲面点、2D 点任何一个不准，姿态就会“整体看似对，但局部贴不上”。([维基百科][2])

# 2. 你接下来最该做的是“贴合误差可视化”

不要再靠肉眼调 `radiusTop / radiusBottom / height / thetaLength / offsetX`。你需要先知道偏差在哪里。

在画面上把参与 PnP 的点重投影出来：

```text
绿色点：OpenCV 识别到的真实图像点
红色点：根据当前 rvec/tvec + 3D 曲面模型 projectPoints 得到的投影点
线段：绿色点 → 红色点
```

如果红绿点整体平移，说明是：

```text
offset / principal point / object-fit crop / cameraMatrix 问题
```

如果中心准、左右边缘不准，说明是：

```text
曲率 thetaLength / 半径 / 曲面模型问题
```

如果上面准、下面不准，说明是：

```text
上下半径 / height / 标签真实高度映射问题
```

如果近处准、远处不准，说明是：

```text
相机内参 fx/fy/fovScale 问题
```

如果一转角度就漂，说明是：

```text
2D-3D 点映射不准，或者目标图曲面形变没有被建模
```

你现在已有 `computeReprojectionError()`，但只是一个平均值。平均值会掩盖问题。你需要输出：

```text
centerError
leftError
rightError
topError
bottomError
maxError
medianError
```

平均 4px 可能看似不错，但如果左边 2px、右边 18px，肉眼就会觉得贴不上。

# 3. 你的 `thetaLength` 不应该靠手调，应该由真实尺寸算出来

你现在有 `thetaLength: 73`，但这个值如果不对应真实标签弧长，就很难贴合。

真实公式应该是：

```text
弧度 angleRad = 标签实际宽度 / 瓶身半径
角度 thetaLength = angleRad * 180 / π
```

例如：

```text
标签宽度 = 72mm
瓶身半径 = 30mm

theta = 72 / 30 = 2.4 rad ≈ 137.5°
```

如果你手调成 73°，那么视频左右边缘一定收缩错。

所以不要只用 UI slider 猜。你要在后台或配置里加入：

```json
{
  "labelPhysicalWidthMm": 72,
  "labelPhysicalHeightMm": 95,
  "bottleRadiusTopMm": 30,
  "bottleRadiusBottomMm": 31,
  "labelTopOffsetMm": 0,
  "labelBottomOffsetMm": 0
}
```

然后自动算：

```js
const thetaLengthRad = labelPhysicalWidthMm / radiusMm;
const thetaLengthDeg = THREE.MathUtils.radToDeg(thetaLengthRad);
```

你的 `height` 也应该来自：

```text
height = labelPhysicalHeight / labelPhysicalWidth 或真实 mm 比例归一化
```

现在如果 `height`、`radius`、`thetaLength` 不是同一个真实单位体系，视觉上一定会错。

# 4. 改掉“用 height / H 当统一 scale”的映射方式

你现在的映射逻辑大概是：

```js
const scale = height / H;
const u_centered = u - W / 2;
const Y = (H / 2 - v) * scale;
const theta = (u_centered * scale) / r_at_y;
```

这个有个隐含假设：

```text
横向像素比例 = 纵向像素比例
```

但你的目标图可能被裁剪、压缩、重新导出、视频比例也可能不一致。更稳的写法应该拆开：

```js
const labelPhysicalWidth = config.labelWidth;   // 比如 1.0
const labelPhysicalHeight = config.labelHeight; // 比如 1.33

const xArc = (u / refWidth - 0.5) * labelPhysicalWidth;
const y = (0.5 - v / refHeight) * labelPhysicalHeight;

const t = v / refHeight;
const r = radiusTop * (1 - t) + radiusBottom * t;

const theta = xArc / r;

return {
  X: r * Math.sin(theta),
  Y: y,
  Z: r * Math.cos(theta)
};
```

也就是说，不要让 `height / H` 同时控制横向和纵向。横向应该由 **标签实际弧长宽度** 控制，纵向应该由 **标签实际高度** 控制。

这是你贴不准的高概率原因之一。

# 5. 相机内参不能继续只靠 `fovScale`

你现在的 camera matrix 是：

```js
fx = trackW * fovScale
fy = trackW * fovScale
cx = trackW / 2
cy = trackH / 2
```

这只是粗略估计。PnP 对内参敏感，尤其是你要“无缝贴合”时。PnP 问题本身就是根据 3D 世界点和 2D 图像点估计相机 6DOF 姿态，模型里明确需要相机内参矩阵 K，包括焦距和主点。([维基百科][2])

下一步至少做两个优化：

### A. `fx` 和 `fy` 分开调

不要：

```js
fx = trackW * fovScale;
fy = trackW * fovScale;
```

改成：

```js
fx = trackW * config.fxScale;
fy = trackH * config.fyScale;
cx = trackW * config.cxRatio;
cy = trackH * config.cyRatio;
```

UI 加：

```text
fxScale
fyScale
cxOffset
cyOffset
```

否则你只能调一个焦距参数，解决不了上下/左右不同的偏差。

### B. 加畸变参数

现在你是：

```js
distCoeffsMat = cv.Mat.zeros(4, 1, cv.CV_64F);
```

这等于假设摄像头无畸变。但手机广角摄像头会有明显径向畸变。越靠画面边缘，越容易贴不上。

至少加：

```text
k1
k2
p1
p2
```

如果不想做完整相机标定，也可以先手动调 `k1`：

```js
distCoeffs = [k1, k2, p1, p2]
```

商业级平台不会靠一个 `fovScale` 解决所有设备。

# 6. 目标图和视频纹理必须建立同一套 UV 坐标

无缝贴合还有一个常被忽略的问题：**识别用的是 `mark.jpg`，播放用的是 `attach.mp4`，它们是否完全同构？**

必须满足：

```text
mark.jpg 的左上角 = attach.mp4 第一帧内容的左上角
mark.jpg 的有效标签区域 = attach.mp4 的有效视频区域
二者宽高比例一致
没有额外透明边、黑边、裁剪、缩放
没有镜像方向差异
```

你现在代码里对视频和 label 都做了：

```js
texture.repeat.x = -1;
texture.offset.x = 1;
```

这个很危险。镜像也许解决了某个方向问题，但如果识别点坐标没有同样镜像，或者前后摄像头切换时又镜像一次，就会出现“中心能对，边缘不对”的假象。

建议你做一个调试模式：

```text
不用视频
直接把 mark.jpg 作为贴图贴回瓶身
```

如果 `mark.jpg` 都不能和真实酒标无缝重合，说明问题是：

```text
几何 / 相机 / 曲面模型
```

如果 `mark.jpg` 能重合，但 `attach.mp4` 不能重合，说明问题是：

```text
视频内容和 mark.jpg 的 UV / 裁剪 / 镜像 / 比例不一致
```

这个测试非常关键。不要跳过。

# 7. 单一整体 PnP 不够，下一步要做“局部曲面校正”

真实商业级贴合通常不是只靠一个整体 pose。一个整体 pose 只能解决：

```text
整个瓶子的空间位置和旋转
```

但不能解决：

```text
酒标局部印刷误差
瓶身非理想圆柱
纸张贴歪
边缘轻微翘起
摄像头畸变
曲率局部变化
```

所以你需要增加一层 **局部 deformation correction**。

简单做法：

```text
把标签分成 4x4 或 6x6 网格
每个网格点根据当前 Homography / optical flow / projectPoints 误差做微调
视频贴图不再是单个 CylinderGeometry
而是更细分的曲面网格
每个顶点允许小幅 offset
```

Three.js 这边可以把 CylinderGeometry 的段数提高，并允许动态修改顶点：

```text
radialSegments: 32 或 64
heightSegments: 8 或 12
```

然后根据局部误差做轻微调整。

注意：这不是让模型乱变形，而是在整体 PnP 姿态基础上，补偿局部误差。

# 8. 你应该增加一个“4角/多点手动标定模式”

Kivicube / 8th Wall 这种平台通常会把复杂标定隐藏在工具链里。你自己做，不能完全指望算法一次自动对准。

建议加一个标定模式：

```text
用户把瓶子正对摄像头
系统显示虚拟 label 边框
用户拖动 4 个角/8 个控制点
保存 calibration profile
```

保存内容：

```json
{
  "thetaLength": 126.4,
  "labelWidth": 1.0,
  "labelHeight": 1.33,
  "radiusTop": 0.72,
  "radiusBottom": 0.76,
  "offsetX": 0.03,
  "offsetY": -0.02,
  "offsetZ": 0.01,
  "rotX": 1.5,
  "rotY": -2.0,
  "rotZ": 0.8,
  "fxScale": 1.12,
  "fyScale": 1.06,
  "cxRatio": 0.502,
  "cyRatio": 0.493
}
```

这一步很实用。因为你现在靠滑块调，缺少“目标函数”。你需要让用户调的是“可见边框”，而不是调抽象参数。

# 9. 推荐你的下一版优化顺序

不要同时改一堆。按这个顺序来：

## 第一步：做 mark.jpg 回贴测试

```text
真实瓶子上有 mark.jpg
AR 里也贴 mark.jpg
看是否能完全重合
```

结论判断：

```text

mark.jpg 重合但视频不重合：视频 UV 问题
```

## 第二步：把贴合误差画出来

显示：

```text
绿色真实点

误差线
```

没有这个工具，你后面会继续凭感觉。

把横向弧长和纵向高度分开：

```js
const xArc = (u / refWidth - 0.5) * labelPhysicalWidth;
const y = (0.5 - v / refHeight) * labelPhysicalHeight;
const theta = xArc / r;
```

不要再用 `height / H` 同时控制横向和纵向。

## 第四步：加入真实物理尺寸配置


## 第五步：相机内参加 fx/fy/cx/cy

# 10. 最关键的判断标准

你现在不要追求“看起来差不多”。要用指标：

```text
中心区域 reprojection error < 3px
左右边缘 reprojection error < 6px
上下边缘 reprojection error < 6px
最大误差 < 10px
连续转动时误差不系统性向一边偏
```

如果误差是随机抖动，是跟踪问题。

如果误差稳定偏向某个方向，是标定问题。

如果中心准、边缘错，是曲率/畸变问题。

如果正面准、侧面错，是曲面模型问题。

如果 mark 图准、视频错，是 UV/素材问题。

## 结论

你现在已经过了“性能优化”阶段，下一阶段是：

```text
从 Tracking Engine
升级到 Calibration Engine
```

下一步最值得做的不是继续换 ORB/SIFT，也不是继续调 LK 光流，而是这三个：

```text
1. mark.jpg 回贴测试
2. 红绿重投影误差可视化
3. 物理尺寸驱动的曲面映射模型
```

做完这三步，你会非常清楚到底是：

```text
视频素材错
曲率错
相机内参错
瓶身模型错
还是目标点映射错
```

现在继续凭肉眼调滑块，很难达到“无缝贴合”。

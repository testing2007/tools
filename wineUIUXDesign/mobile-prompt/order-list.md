
一、定位

1. 这是“酒类优先”的订单列表页；
2. 页面宽度按 375px 设计；
3. 页面应支持从 ./member-center.html 或 ./checkout.html 进入，并提供返回 ./index.html 的入口。

二、页面结构

1. 顶部栏：返回、标题、搜索入口；
2. 状态 tabs，至少包含：
   - 全部
   - 待支付
   - 待发货
   - 待收货
   - 已完成
   - 售后中
3. 订单卡片列表，每张订单卡片需展示：
   - 订单号
   - 订单状态
   - 下单时间
   - 酒款缩略信息
   - 酒名
   - 品牌
   - 产区
   - 年份
   - 数量
   - 实付金额
   - 瑕疵酒/盲盒标志
4. 每张卡片内必须增加酒类专属入口：
   - 品牌故事
   - 产区地图
   - 搭餐建议
   - 口感档案
   - 适饮窗口
   - 真伪/批次溯源
   - 数字酒窖入口
   - AI 侍酒师入口
5. 页面底部可加入“继续逛酒”推荐模块。

三、必须包含的交互要点

1. Tab 切换联动订单列表；
2. 顶部搜索支持按订单号/酒名/品牌前端检索；
3. 待支付订单必须展示支付倒计时；
4. 每张订单卡片的操作按钮至少包含：
   - 去支付
   - 查看详情
   - 再来一单
   - 申请售后
   - 确认收货
5. 点击“真伪/批次溯源”弹出批次信息层；
6. 点击“数字酒窖入口”弹出“入窖/提酒”说明；
7. 点击“AI 侍酒师入口”弹出快捷提问区；
8. 点击“品牌故事/产区地图/搭餐建议/口感档案”展示底部弹层或卡片展开；
9. 订单取消、确认收货需有确认弹窗；
10. 页面支持空列表状态与无搜索结果状态。

四、必须体现的酒类专属内容

1. 订单卡片不能只展示金额和数量，必须体现酒类属性；
2. 必须出现品牌故事、产区地图、搭餐建议、口感档案、适饮窗口；
3. 必须出现真伪/批次溯源入口、数字酒窖入口、AI 侍酒师入口；
4. 瑕疵酒与盲盒订单必须有特殊风险提示或标签。

5. 文案全部中文；
6. 页面内 CSS、JS 直接写在 HTML 中；
7. 所有链接使用相对路径；
8. 最终直接输出完整 html 代码，不要输出解释。

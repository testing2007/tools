
一、技术要求

1. 使用纯 HTML + CSS + 原生 JavaScript 实现；
2. 所有页面独立成单独 html 文件；
3. 使用 mock 数据，不依赖后端接口；
5. 页面要适合手机浏览器预览；
6. 不使用复杂构建工具，不使用 Vue/React；
7. CSS 尽量写在每个页面内，便于单文件查看；
9. 页面之间可通过超链接跳转；
10. 最后生成一个 index.html，作为移动端原型导航页，可以进入每个功能页。

二、业务定位
这是一个“酒类优先”的电商小程序原型，不是通用商城。
商品页和功能页必须突出酒类特色，不能只做普通商品卡片。
除基础商品信息外，必须重点体现以下酒类专属模块：

- 品牌故事
- 产区地图
- 搭餐建议
- 口感档案
- 适饮窗口
- 真伪/批次溯源
- 数字酒窖入口
- AI侍酒师入口

四、首页设计要求
首页必须体现“酒类优先”：

1. 顶部搜索栏 + banner
2. 酒类分类入口（红酒、白酒、威士忌、香槟、精酿等）
3. 品牌故事专区
4. 热门产区专区（地图卡片）
5. 搭餐推荐专区
6. 本周适饮推荐
7. 秒杀/限时折扣入口
8. 福袋盲盒入口
9. 数字酒窖入口
10. AI侍酒师入口
11. NFC互动活动入口
12. 瑕疵酒专区入口

五、商品详情页要求
必须突出酒类专业信息，页面结构建议包括：

1. 商品主图轮播
2. 商品名称、副标题、评分、销量
3. 价格区（原价、活动价、会员价）
4. 口感档案（酸度、甜度、单宁、酒体、香气）
5. 适饮窗口
6. 产区地图
7. 品牌故事
8. 搭餐建议
9. 真伪/批次溯源入口
10. 数字酒窖入口
11. AI侍酒师入口
12. 用户评价
13. 购买按钮
14. 若商品属于瑕疵酒，要有明显提示标签

六、功能页要求
每个功能页都要体现“营销功能 + 酒类场景”结合，不能只是普通表单。
例如：

- 企业员工礼品卡：面向企业采购、员工福利发放、礼品兑换码、兑换说明
- 酒局游戏：开房间、邀好友、多人参与、酒桌互动、排行榜、奖品红包
- 葡萄酒养成计划：种葡萄、浇水、成长阶段、好友互访、收获奖励
- NFC多人瓜分红包：NFC触碰动画、参与人数、红包进度、开奖记录
- AR体验：扫码看酒标、侍酒演示、产地故事、3D展示入口
- 数字藏酒：我的藏酒、编号、仓储位置、年份、状态、提酒入口、转赠记录
- 福袋盲盒：规则说明、每月/每年限购、低价抢购、酒款未知、瑕疵说明、价值承诺
- 瑕疵酒专区：个人自饮推荐、瑕疵说明、折扣展示、介意者慎拍说明

七、交付要求

1. 输出完整项目文件内容；
2. 先输出 index.html；
3. 再依次输出其他页面；
4. 每个 html 文件都必须可独立打开预览；
5. 所有链接使用相对路径；
6. mock 数据要贴近酒类场景，包含酒名、品牌、产区、年份、口感描述等。

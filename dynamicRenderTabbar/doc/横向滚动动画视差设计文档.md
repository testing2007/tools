> 项目：`dynamicRenderTabbar`

> 日期：2026-04-21

## 一、动画需求

### 1.1 整体效果

首页顶部有一个横向 Banner，展示两组「底图 + 浮层文字」，效果参考优剪 App 风格：浮层文字在底图上方漂浮，手动拖拽时文字跟随手指，松手后以弹簧方式回弹或触发翻页过场。

### 1.2 图层结构

```
┌─────────────────────────────────┐
│  浮层文字 (float_text.png)       │  ← 透明 PNG，带文字
├─────────────────────────────────┤
│  底图 (under.jpg / under.png)   │  ← 背景图片
└─────────────────────────────────┘
```

两组图片资源（均放在 `assets/`）：

| 资源 | 说明 |
|------|------|
| `1_float_text.png` + `1_under.jpg` | Slide 0 |
| `2_float_text.png` + `2_under.png` | Slide 1 |

### 1.3 交互需求

| 场景 | 行为 |
|------|------|
| **手指按住拖动** | 只有浮层文字跟随手指左右移动，底图完全静止不动 |
| **拖动未冲破阈值，手指抬起** | 浮层文字弹回原位，有弹簧感（轻微过冲再回落） |
| **冲破阈值后，手指抬起** | 触发翻页：当前浮层文字飞出，下一张浮层文字飞入，底图同步淡入 |
| **自动轮播** | 每 3.6 秒自动切换，循环往复，手动操作时暂停 |

### 1.4 阈值设计——速度感知动态阈值

快速轻扫只需很短距离即可触发翻页；慢速拖动需要约半屏距离才触发，通过**综合评分**实现：

```
score = 归一化位移量 + |速度(px/ms)| × 速度权重系数

归一化位移量 = |totalDx| / stageWidthPx    // 0 ~ 1
速度权重系数 = 2.0（默认）

score >= 0.5  → 触发翻页
score <  0.5  → 弹回
```

**示例**：

- 快速轻扫 `v = 0.3 px/ms`：velScore = 0.6 → 即使位移很小也触发
- 慢速拖动 `v ≈ 0`：需要位移超过半屏 (normDist ≥ 0.5) 才触发

### 1.5 技术约束

- **禁止**使用任何微信小程序滑动组件（`swiper`、`scroll-view` 等）
- 仅使用 `view`、`image`、`text` 原始组件
- 兼容基础库 ≥ 2.4.4

## 二、动画算法设计

### 2.1 整体双线程架构

微信小程序有独立的 JS 线程与渲染线程，二者通过通信桥异步交互。

```
┌──────────────────────────────────────────────────────────┐
│               渲染线程（Render Thread / WebView）         │
│                                                          │
│  hero-drag.wxs（WXS 脚本）                               │
│  · touchmove → selectComponent('#floatXw').setStyle()    │
│    直接在渲染线程修改 DOM 样式，零通信桥延迟               │
│  · touchStart / touchEnd → callMethod() 通知 JS          │
└──────────────────────┬───────────────────────────────────┘
                       │ callMethod（仅 start/end 时，频率极低）
┌──────────────────────▼───────────────────────────────────┐
│                   JS 线程（AppService）                   │
│                                                          │
│  index.js                                                │
│  · onWxsStart：停止轮播，记录时间戳                       │
│  · onWxsEnd：手势分析 → 决策翻页 / 弹回                   │
│  · _commitFlip / _springBack：setData 切换 CSS class      │
│    → CSS transition 承担实际动画（无 JS 帧循环）           │
└──────────────────────────────────────────────────────────┘
```

### 2.2 DOM 层次结构

```
.hero-stage（触摸区，overflow:hidden）
 ├── <image>.hero-under   1_under.jpg    ← 始终在底，opacity 固定 1
 ├── <image>.hero-under   2_under.png    ← opacity 受 JS 控制
 ├── <view id="float0w">  .hero-float-wrap   ← WXS / JS 控制 transform
 │    └── <image>.hero-float  1_float_text.png  ← JS 控制 opacity
 └── <view id="float1w">  .hero-float-wrap
      └── <image>.hero-float  2_float_text.png
```

> **关键设计**：DOM 顺序决定层叠关系，**不使用** `z-index` inline style，
> 避免频繁改变 z-index 引发 Layout Recalculation，进而导致闪烁。

### 2.3 底图切换逻辑（极简模型）

只需控制 `under1Opacity` 一个值，`under0` 始终不透明：

| `under1Opacity` | 视觉效果 |
|---|---|
| `0` | `2_under.png` 全透明，`1_under.jpg` 透出显示 |
| `1` | `2_under.png` 完全覆盖，Slide 1 底图可见 |

翻页时由 CSS Transition 平滑过渡：

```css
.hero-under.fade-600 {
  transition: opacity 600ms ease-out;
}
```

### 2.4 WXS 拖拽追踪（hero-drag.wxs）

```
touchStart
  → 检查 dataset.animating（动画中则忽略）
  → 记录 _startX，_active = true
  → callMethod('onWxsStart')

touchMove
  → dx = currentX - _startX
  → 软夹：|dx| ≤ stageW × 0.55   （留有阻力感）
  → _lastDxPx = dx
  → selectComponent('#float{cur}w').setStyle({
      transform: 'translateX(' + dx + 'px)'
    })                             ← 渲染线程直接操作，零延迟

touchEnd
  → _active = false
  → callMethod('onWxsEnd', { totalDxPx, lastDxPx })
```

WXS 模块级变量 `_active` 防止 touchEnd 丢失时状态泄漏。

### 2.5 手势结算（JS onWxsEnd）

```js
velocity  = totalDxPx / elapsedMs            // px/ms，正=右划
normDist  = |totalDxPx| / stageWidthPx       // 归一化距离 0~1
velScore  = |velocity|  * CONFIG.velocityBoost
score     = normDist + velScore

flipDir   = totalDxPx < 0 ? 1 : -1          // 1=前进 -1=后退

if (|lastDxPx| < 5px) → 视为点击，跳过动画
if (score >= CONFIG.scoreTrigger) → _commitFlip(cur, next, flipDir)
else                              → _springBack(cur)
```

### 2.6 WXS → WXML 样式控制权交接

WXS 的 `setStyle` 与 WXML 数据绑定产生的 inline style **作用于同一元素**，同时存在时**后写者覆盖**。手指抬起后，需将 transform 控制权从 WXS 交还给 JS/CSS，步骤如下：

```
① JS setData({
     float{cur}X:     pxToRpx(lastDxPx),  // WXML 同步到当前拖拽位置
     float{cur}Trans: 'trans-none',        // 阻止因同步值变化触发 transition
     clearVersion:    clearVersion + 1     // 触发 WXS 的 change: 观察器
   })

② WXS onClear（change:data-clear-version 触发，在渲染线程执行）：
   selectComponent('#float0w').setStyle({ transform: '' })  // 清除 WXS style
   selectComponent('#float1w').setStyle({ transform: '' })  // WXML style 重新生效

③ setTimeout 16ms → 确认渲染完成后，启动 CSS transition 动画
```

**单位换算**（WXS 用 px，WXML 用 rpx）：

```
rpxRatio = windowWidth / 750
pxToRpx(px) = px / rpxRatio

示例 —— 375px 屏幕：rpxRatio = 0.5
  50px = 50 / 0.5 = 100rpx ✓
```

### 2.7 翻页动画（_commitFlip）— 两步 setData 保证 CSS Transition 触发

CSS transition 需要在**上一帧已"提交"元素的起始位置**的前提下，才能正确感知 from → to 变化。若在同一 setData 批次中同时"启用 transition class"和"改变 transform 值"，某些情况下浏览器会视为初始值忽略过渡。因此采用分步策略：

```
Step-A（T = 0ms）：
  float{next}X       = enterRpx     ← 进入侧：瞬间定位到画面边缘起点
  float{next}Opacity = 1
  float{next}Trans   = 'trans-none' ← 不触发 transition，直接到位
  float{cur}Trans    = 'trans-flip' ← 离开侧：提前挂上 transition class
  under1Trans        = 'fade-600'   ← 底图：提前挂上 transition class

  （此时渲染线程完成一帧：进入侧在 enterRpx，离开侧还在原位）

Step-B（T = 16ms，等 1 帧后）：
  float{next}Trans  = 'trans-flip'  ← 进入侧激活 transition
  float{cur}X       = exitRpx       ← 离开侧值变化 → 上一帧class已挂 → transition 触发 ✓
  float{next}X      = 0             ← 进入侧值从 enterRpx → 0 → transition 触发 ✓
  under1Opacity     = underEnd      ← 底图 opacity 变化 → fade-600 触发 ✓

Cleanup（T = 16 + flipDuration + 100ms）：
  重置 float{cur} 的 opacity/X/Trans 为初始值
  重置 float{next}Trans = ''，under1Trans = ''
  activeSlide = next
  isAnimating = false
```

**方向映射**：

| 手势 | flipDir | exitRpx（离开侧目标） | enterRpx（进入侧起点） |
|---|---|---|---|
| 左滑（前进） | `1` | `-stageRpx` | `+stageRpx` |
| 右滑（后退） | `-1` | `+stageRpx` | `-stageRpx` |

### 2.8 弹回动画（_springBack）— 弹簧曲线

同样采用两步 setData，确保 trans-spring class 在值变化前一帧已挂载：

```
Step-A（T = 0ms）：
  float{cur}Trans = 'trans-spring'  ← 挂上弹簧 transition（不改 X）

Step-B（T = 16ms）：
  float{cur}X = 0                   ← 从 lastRpx → 0，transition 触发 ✓
                                       (cubic-bezier 产生过冲，弹簧感)

Cleanup（T = 16 + springDuration + 100ms）：
  float{cur}Trans = ''
  isAnimating = false
```

CSS 弹簧曲线（近似 ease-out-back，轻微过冲）：

```css
.hero-float-wrap.trans-spring {
  transition: transform 420ms cubic-bezier(0.34, 1.56, 0.64, 1);
}
```

参数 `1.56` 是过冲系数，让文字在归位前略微超出终点再轻微弹回。

### 2.9 CSS Transition Class 一览

| Class | 用途 | CSS |
|---|---|---|
| `trans-none` | 禁止过渡（瞬间到位） | `transition: none !important` |
| `trans-flip` | 翻页滑出 / 滑入 | `transform 600ms cubic-bezier(0.16,1,0.3,1)` |
| `trans-spring` | 弹回（过冲） | `transform 420ms cubic-bezier(0.34,1.56,0.64,1)` |
| `fade-600` | 底图淡入 / 淡出 | `opacity 600ms ease-out` |

## 三、闪烁问题分析与解决

### 3.1 问题现象

在手指拖动（`touchmove`）过程中，浮层文字出现明显的抖动 / 闪烁，无法实现丝滑跟手。

### 3.2 根本原因：双线程通信桥延迟

微信小程序采用**双线程架构**，JS 线程与渲染线程完全隔离，通过异步通信桥（桥接层）交换数据：

```
JS 线程（AppService）            渲染线程（WebView）
─────────────────             ─────────────────────
touchmove 触发
↓
计算 dx
↓
setData({ floatX: dx })  ──→  [序列化 → 通信桥 → 反序列化]
                          ~~~ 延迟约 5~20ms ~~~
                          ──→  VDOM Diff → 重算样式 → Repaint
```

`touchmove` 每秒可能触发 60~120 次，而每次 `setData` 至少需要约 5~20ms 才能到达渲染线程。当新的 `touchmove` 数据涌入时，上一帧尚未渲染完毕，导致**帧跳变（frame skipping）**，即闪烁。

> **误区**：移除 CSS `transition` 并不能解决闪烁，反而会使每次 setData 的跳变更明显。

### 3.3 解决方案：WXS 在渲染线程直接操作样式

微信小程序提供 **WXS（WeiXin Script）**，其 touch 事件处理器直接运行在**渲染线程**，可通过 `ComponentDescriptor.setStyle()` 同步修改元素样式，**完全绕过通信桥**：

```
旧方案（闪烁）：
touchmove → JS线程 → [通信桥 ~10ms] → 渲染线程 → Repaint
                ↑ 异步延迟，多帧数据堆积 → 帧跳变

新方案（无闪烁）：
touchmove → WXS（已在渲染线程）→ setStyle() → 同步 Repaint
                ↑ 同线程，零延迟，每帧只绘制一次
```

### 3.4 WXS 与 WXML 的样式冲突及解决

WXS `setStyle` 与 WXML 数据绑定产生的 `style` 属性都作用于同一元素的 inline style，**同属性时后写者覆盖先写者**。

```
拖拽中：
  WXML style="transform:translateX(0rpx)"  ← 数据绑定（float0X=0）
  WXS  setStyle({transform:'translateX(50px)'})  ← 后写，覆盖 ✓
  → 元素最终 transform = translateX(50px)

手指抬起，交接时：
  WXS  setStyle({transform:''})           ← WXS 主动清除自己的写入
  → WXML 数据绑定重新生效（已同步到 pxToRpx(lastDx) 的值）
  → 无视觉跳变 ✓
  → CSS transition 从此值平滑动画至目标 ✓
```

### 3.5 WXS 使用限制及应对策略

| WXS 限制 | 应对方案 |
|---|---|
| 无 `setTimeout` / `setInterval` | 动画由 CSS Transition 承担，无需 JS 帧循环 |
| 无法直接读取 Page `data` | 通过 `data-*` 属性传入，从 `e.currentTarget.dataset` 读取 |
| 与 JS 通信异步（callMethod） | 仅在 touchStart / touchEnd 低频通知 JS，touchmove 全程不通信 |
| 语法为 ES5（兼容旧版） | 全部使用 `var`、`function` 关键字声明 |
| `requestAnimationFrame` 不可用 | 不需要，CSS Transition 直接在渲染线程运行 |

## 四、可配置参数说明

所有动画参数集中在 `index.js` 顶部的 `CONFIG` 对象，便于未来后台配置编辑器读取并注入：

```js
var CONFIG = {
  slideCount:     2,      // 幻灯片总数
  autoInterval:   3600,   // 自动切换间隔（ms）
  stageRpx:       702,    // hero-stage 宽度 rpx（= 750 - 24×2 页面 padding）
  flipDuration:   600,    // 翻页过场动画时长（ms）
  springDuration: 420,    // 弹回动画时长（ms）
  velocityBoost:  2.0,    // 速度对触发分数的贡献系数（越大越灵敏）
  scoreTrigger:   0.5     // 综合阈值（越小越容易触发翻页）
};
```
